# ds/toolret — ToolRet metatool

## Source
- Queries: https://huggingface.co/datasets/mangopy/ToolRet-Queries `metatool/queries-00000-of-00001.parquet`
- Tools: https://huggingface.co/datasets/mangopy/ToolRet-Tools `customized/tools-00000-of-00001.parquet`
- Downloaded with curl to `data/toolret/`, read with pandas/pyarrow.
- All 200 metatool queries have category `customized`; the 102 distinct gold tool ids all
  exist in the customized library, so the library is exactly those 102 tools (>= 100, no
  second ToolRet subset was needed). Queries: 200 (179 single-gold, 21 double-gold), all English,
  setting "all".

## Grouping
Tool docs carry no category field and ids (`metatool_which_tool_NN`) carry no namespace, so
groups come from clustering: BM25 (k1=1.5, b=0.75) term-score vectors of name+description,
L2-normalized rows, KMeans(k=round(sqrt(102))=10, random_state=0, n_init=10) — sklearn, seed 0.
Group names = the 2 tool-name tokens most distinctive to the cluster (in-cluster count minus
count in other clusters); group cover words = those 2 name tokens.

## Cover word rule (deterministic, in build_tree.py)
1. tool name split on `-`/`_`/camelCase, lowercased, stopwords/1-char tokens dropped;
2. fill with description tokens by descending IDF (IDF over the 102 name+description docs,
   lowercase `[a-z][a-z0-9]+`, stopword list in build_tree.py) until 5 covers total.
Description three-part form: `Use when <first sentence of tool description>: covers w1, ...`,
truncated to 200 chars. Skill directory name = slugified tool name (lowercase alnum+hyphen);
frontmatter `name` equals the directory name. Body = full tool documentation JSON (truncated
to 8000 chars in skills.jsonl).

## Tree
- `tree/`: root / 10 groups / 102 leaves; `flat/`: root / 102 leaves. Built by
  `build_tree.py`, then `holon.py sync` + `holon.py validate` (both pass:
  113 / 103 skills valid and in sync).
- `organizer_cli.py lint tree` reports 112 errors, ALL of them "triggers needs >= 3 entries"
  (the dataset ships no trigger sentences and none were fabricated, per SPEC); plus
  3 warnings (one duplicated group/leaf name `research-finder`, short cover words) and 4 hints.

## Methods (runs/*.jsonl)
- holon-tree: `organizer_cli.route()` imported in-process on `tree/`. Leaf landing ->
  ranked=[tool]; landing on a group/root or AMBIG -> ranked=[]. Stop stats:
  leaf 28, group 13, root 12, ambiguous 147 of 200. read_bytes = SKILL.md bytes on the route path.
- flat-literal: same covers, all leaves under root. Stops: leaf 28, root 12, ambiguous 160.
- bm25-desc / bm25-body: rank_bm25 BM25Okapi over name+description (+body), top20.
  read_bytes = sum of all candidates' indexed text bytes (11,185 / 25,940).
- dense: fastembed BAAI/bge-small-en-v1.5, name+description, cosine top20, vectors cached
  in `emb/`. read_bytes = all candidate description bytes.
- hybrid: RRF(k=60) of bm25-desc and dense rankings; read_bytes = 2x description bytes.

## Known biases
- No real taxonomy: the KMeans groups are noisy (largest cluster holds ~37 tools) and group
  names are tool-name tokens, so holon-tree ambiguity at the root is high (147/200) — many
  queries contain cover words of tools in several groups.
- Tool descriptions are short and formulaic; bm25-desc and bm25-body differ little.
- 21 queries have 2 gold tools, capping Recall@5 influence of the second gold.
